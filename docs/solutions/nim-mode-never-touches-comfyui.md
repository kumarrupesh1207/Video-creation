# Scheduled comic render crashed on ComfyUI although `comic.image_mode: nim`

Problem: the first scheduled "Aurora Render" (channel shinobi) died with `Connection refused http://127.0.0.1:8188/upload/image` while ComfyUI was down. The comic path had called `LocalComfyUIProvider.generate_with_reference` (local_comfyui.py: `upload_image` of the locked-cast reference for IP-Adapter).
Root cause: in `nim` mode, any NIM failure (here most likely the daily cap: the ledger showed 25/25 credits for that day) fell back to ComfyUI for the REMAINING panels (`_panel_images`, added when NIM became the default). The fallback uploads the reference image straight to :8188 with no check, so a dead server became an unhandled crash, and the fallback contradicted "nim mode = NIM only".
Fix (`aurora/comic.py`): config `comic.nim_comfy_fallback: false` (default). In `nim` mode a NIM failure now stops the reel with a clear error ("NIM failed after N/6 panels (...); ComfyUI fallback is OFF") and never touches ComfyUI; the locked cast works text-only on NIM (verbatim description + fixed seed; the cast reference image is only used by the explicit `comfy`/`auto` modes or the opt-in fallback). With the flag on, `_comfy_up()` preflights `/system_stats` (then `/queue`) first; if ComfyUI is down it logs a WARNING and stops with "not reachable" instead of crashing mid-upload.
Rule: ComfyUI is an optional enhancement. Anything optional must be preflighted and skipped with a logged warning; it must never be able to crash a render. Tests: `tests/test_comic.py` (nim-mode reel renders with ComfyUI down and a cast reference, explicit-failure paths, preflight order). 
How to recognise: `ConnectionError ... 8188` in a run that should have been NIM-only; credits ledger at the daily cap (`outputs/costs/nvidia_nim-credits.json`).
